# RAG + собственный классификатор + работающий HTTP

Изменения выполнены локально2026-10-30. Источники: предоставленные DOCX,
handout/rules.json иtaxonomy.json. Внешний GitHub вернул404; по уточнению пользователя
создан собственный классификатор. Код, веса и метрики того репозитория не выдаются
за проверенные. Данные и производные выборки остаются только в `.private`.

## Что исправлено

Расширены общие RU/KK/UZ поисковые подсказки: перефразированные оскорбления,
споры об обмене имуществом, RMT, формы слов о броне. E5 получает исходный запрос;
подсказки расширяют лексический поиск. Это признаки возможной темы, а не вердикт.
На наблюдаемом наборе нужный источник в top1:6→10из24, top5:13→23,
top10:14→24. Эти вопросы использовались при отладке, поэтому это dev-измерение.

Фильтр больше не выбрасывает эти темы из-за отсутствия буквального слова.
Процедурные пункты не заполняют контекст вместо основного правила. Для событий
разделены явное отрицание, основной контекст и ссылка на чужое событие; при
неоднозначности правило не выбирается наугад. Платёжный/аккаунтный FAQ по-прежнему
не выдумывается. Legacy KK восстанавливается с учётом контекста, исходный запрос
не изменяется. Инструкция генератору требует каноническую ссылку для ответа по
правилу. Вывод увеличен160→224токена; prompt≤1024, context1536, лимит runtime≤256.

## Собственный классификатор

Один общий E5 CPU используется для поиска и классификации. Обучена14-классовая
линейная матрица с маской complaint/report и отдельная голова4приоритетов.
777обучающих примеров:693исторических текста со слабыми метками и84синтетических.
188отложенных слабых меток,42отдельно написанных синтетических примера.
Ответы администратора, status/verdict/punishment/violation не признаки и не цели.
Оригинальная validation использована только для исключения пересечений.
CPU-подготовка/обучение42,81с; новых зависимостей, загрузок и внешних API нет.

| Проверка | Категория: согласие с метками | Приоритет: macro-F1 |
| --- | ---: | ---: |
| Обученная голова /188слабых меток |77,66%|0,774|
| Только правила /42синтетических |35,71%|0,315|
| Только обученная голова /42 |57,14%|0,698|
| Сервис: модель + резервные правила /42 |40,48%|0,651|

Это **не человеческая accuracy/F1**. Модель не уверена в33/42случаях; у2из9
уверенных категорий есть ошибка. Поэтому оставлены резервные правила, независимый
порог срочности по полному тексту и обязательный человек. Платежи/аккаунты/админ
не получают менее срочный приоритет из-за слабой головы. Confidence не калиброван.
Нужны настоящие метки, проверка носителями языка и больше редких опасных примеров.
Подробности и воспроизведение: [classifier/README.md](../classifier/README.md).

## Полные ответы модели

Одинаковые36синтетических dev-сценариев, корпус, базовая Q4_K_M, классификатор,
код, порядок и настройки.24сценария требуют ссылку,12допускают отсутствие ссылки.
Ошибки входят в знаменатели и время. Наличие ID не доказывает смысловую применимость.

| Цепочка | Полный вывод /36 | Обязательная ссылка в итоговом ответе /24 | Все наблюдаемые проверки /36 | p50 / sample p95, с |
| --- | ---: | ---: | ---: | --- |
| До исправлений, рабочий адаптер |33|4|16|1,53 /3,31|
| Исправленная, рабочий адаптер |34|21|32|1,80 /4,58|
| Исправленная, кандидат rag-v2 |29|21|26|1,63 /4,61|

Рабочий адаптер сохранён: кандидат чаще не завершает ответ. У рабочего остаются
2обрезанных генерации и2отклонения черновика проверкой языка/вывода;4шаблонных
резервных ответа. На36случаях не наблюдались неизвестные или запрещённые
контекстом канонические ссылки. Это не доказательство отсутствия галлюцинаций.
32/36 означает выполнение конкретных автоматических условий, не слепую оценку
администраторами. Sample p95<5с здесь не подтверждает production SLA или нагрузку.

После измерения дополнительный TCP-запрос выявил фразу MUTE qilinadi, которую
проверка обещаний наказания пропускала. Добавлены RU/KK/UZ варианты и регрессии.
Все72сохранённых вывода повторно проверены новым guard: итоговые ответы не
изменились; прежние метрики сохранены. Изменение policy-хеша отражено отдельно,
время replay не выдаётся за новый замер генерации. Повторный живой UZ-запрос
теперь даёт безопасный шаблон с `draft_action_or_evidence_claim`.

## HTTP и страница

Запуск: `scripts/run-rag.ps1 -Action serve -AdapterVersion smoke -Port 8000`.
Главная страница содержит форму, таблицу метрик,12фактических примеров; `docs`
даёт OpenAPI. Добавлены POST/v1/classify, GET/v1/evaluation и
GET/v1/classifier/metrics. Отчёты не содержат исходных исторических обращений,
админских ответов, путей runtime или секретов. Конфиденциальные данные не
публиковались; доступ только loopback. Host allowlist и запрет чужого Origin
защищают локальную границу; интерфейс использует textContent и CSP.

Фактические TCP-проверки: главная, JS, meta, evaluation, classifier metrics200;
чужой Host400, Origin403; classifier/triage200наRU/KK/UZ. В дополнительном KK
запросе неизвестная ссылка корректно вызвала шаблон; это известный пробел качества,
а не успешное цитирование. RU-ответ дал rules:30:2.1. UZ-обещание наказания после
усиления проверки отклонено. Порядок фактических примеров не меняли ради метрик.

Edge headless с отдельным приватным профилем действительно отрисовал метрики,
интегрированные показатели классификации и12примеров. Проверены DOM и скриншот;
профиль пользователя не использовался. Сервис оставляется работающим по запросу.

Финальная регрессия:263теста +50subtests, exit0; pipcheck exit0. JS проверен
Node и реальным браузером. Документальные локальные ссылки проверены.
Чистая установка на другой машине, внешний pentest и слепая оценка поддержки
не выполнялись. Финальный TCP ready200:классификатор готов,12примеров доступны.
