## Языки и данные

Добавлен анализ RU/KK/UZ/EN с отдельным `und`. Доминантный язык определяется по
содержательным словам, смешение/неопределённость отражаются в reasons. Метаданные,
ники, URL и цитируемые правила маскируются только внутри детектора; полный текст
сохраняется. Emoji/цифры/неизвестная короткая строка не становятся KK из-за сервера.
При `und` запрашивается язык без E5 и без LLM. EN теперь имеет настоящую генерацию,
а не только резервный шаблон. ES/PT шаблоны сохранены, их генерация не оценивалась.

Legacy-таблица из DOCX:ќ→қ,ґ→ғ,ѕ→ң,є→ә,ј→ө,ў→ұ,ї→ү, с сохранением регистра.
Замена ограничена KK/KZ-контекстом или характерным сигналом; неоднозначные буквы
не преобразуются глобально. Это восстановление уже декодированного текста,
а не угадывание произвольной байтовой кодировки HTTP.

Ограниченный словарь опечаток применяется только к поисковому/классификационному
представлению. Исходная реплика, отрицания, номера правил и защищённые имена/URL
сохраняются. Номер игрока — поисковая подсказка, не истинный пункт нарушения.
Утверждения остаются неподтверждёнными; guard отклоняет явный вердикт/заявление
о просмотре изображения на RU/KK/UZ/EN. Это шаблонные проверки, не доказательство
полной безопасности или смысловой правильности.

`has_evidence` означает наличие по счётчикам, не просмотр/валидность доказательства.
Reasons отдельно содержат число images/messageattachments, отсутствие содержимого
и статус утверждений. Счётчики не складываются в выдуманное число уникальных
изображений. Админские ответы и исходы по-прежнему исключены из признаков/промпта.

## Цена CPU-обработки

Классификатор и RAG раньше независимо считали один query-вектор E5 дважды.
Теперь общий RAM LRU:128векторов,300секунд TTL, ключ — хеш точного обработанного
текста и версия энкодера/prefix/pooling. Нет кэша ответов/решений/идентичностей,
нет сохранения запросов на диск. Копии массивов исключают отравление кэша клиентом.
При reload/close он очищается. Максимум vectorpayload196608байт, плюс служебные поля.

Первое сопоставимое CPU-измерение40запросов (генерация отключена):72→36расчётов E5,
p50 28,34→15,75мс, p95 32,95→18,07мс; все поля40ответов совпадают после
исключения поля времени. Повторный идентичный запрос не требует нового E5-вектора.
Анализ языка p50 0,084мс,p95 0,117мс. Это CPU-этап, а не ускорение всей LLM вдвое.
Финальный повтор с хешами кода: p50 28,16→15,33мс,p95 32,73→19,45мс,
72→36векторов и40/40совпавших ответов; анализ языка p95 0,128мс.

## Воспроизведение

```powershell
.\.venv-soup\Scripts\python.exe -X utf8 scripts/evaluate_robustness.py --dry-run
.\.venv-soup\Scripts\python.exe -X utf8 scripts/evaluate_robustness.py --base --output .private/input-v4/new-base.jsonl
.\.venv-soup\Scripts\python.exe -X utf8 scripts/benchmark_input_pipeline.py --output .private/input-v4/new-cpu.json
.\scripts\run-rag.ps1 -Action serve -EvaluationReport .private/input-v4/metrics36.json
```

Выход должен быть новым. Один GPU-процесс за раз; остановите HTTP перед оценкой.
`GET /v1/evaluation` — обновлённые36сценариев; `GET /v1/robustness` — отдельные40
и10примеров на RU/KK/UZ/EN/und. Указанные проверки подтверждены сохранёнными
результатами; они не являются независимой человеческой оценкой. Данные и сырой
вывод остаются в `.private/input-v4`.

Следующий шаг качества: настоящая человеческая разметка, исправленные сотрудником
черновики, шумовые варианты и сбалансированные языки, разделение по заявителю/
времени/близким дубликатам. Дообученный адаптер принимать только после сравнения
качества, безопасности и задержки на отдельном тесте; RAG хранит правила, модель
не должна запоминать их как установленные факты об игроке.
