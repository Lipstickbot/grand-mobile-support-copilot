# Grand Mobile: локальный RAG baseline

Текущий статус после исправлений и границы проверенного качества:
[STATUS.md](STATUS.md) и [итоговая проверка](experiments/quality-v5/RESULTS.md).
В интерфейсе `/v1/quality` сравниваются текущие100сценариев и отдельно16новых
критичных формулировок. На новых категория+p0получились лишь2/16: это существенное
ограничение, даже при прошедших тестах кода. Приведённые ниже36/40метрики — история.

Реализованы разбор обращения, поиск по правилам, черновик ответа, JSON API и
пакетный JSONL. Это исследовательский baseline. Классификация обучена на слабых
метках; confidence не калиброван. Автоматическое закрытие отключено: `needs_human=true`
для всех случаев. Не заявляем готовность к продакшену или выполнение SLA хакатона.
Текущий быстрый запуск: **llama.cpp CUDA + локальный Q4_K_M**, KV-кэш включён.
Текущий выбор — исходная8Bбез LoRA:23/24обязательных ссылок,35/36сценариев проходят
наблюдаемые проверки; p50 1,84с, sample p95 4,09с. Это синтетический набор разработки,
не слепая оценка качества или production SLA.
Свежая более строгая [живая HTTP-проверка100обращений](experiments/quality-live/RESULTS.md)
обнаружила22случая псевдоссылок; нужный пункт сохранился в48/63ответах.
Классификатор на42синтетических примерах:17/42категорий, macro-F1 0,3349.
Прежние35/36 не означают смысловую точность: не все выдуманные обозначения и
неверные рекомендации по наказанию ловились прежними автоматическими проверками.
Текущие результаты: [experiments/inference/RESULTS.md](experiments/inference/RESULTS.md).
История Soup-запуска: [experiments/rag/RESULTS.md](experiments/rag/RESULTS.md).
Новая итерация: [дообучение, HTTP v2 и ограничения качества](experiments/rag-training/RESULTS.md).
Новый адаптер проверен и отклонён; для работы сохранён предыдущий вариант.
Текущие результаты: [RAG v3](experiments/rag-v3/RESULTS.md),
[собственный классификатор](experiments/classifier/README.md).
Обработка RU/KK/UZ/EN/und, опечаток и смешанных сообщений:

## Что используется

- **Qwen3-8B** из репозитория автора, локальная ревизия
  `b968826d9c46dd6066d109eabc6255188de91218`. Эти же веса локально преобразованы
  в Q4_K_M официальным конвертером. Инференс: llama.cpp b11960 CUDA12.4,
  RTX3060 Laptop6GB, KV-кэш, native Flash Attention, один слот1536токенов.
- Сохранён экспериментальный LoRA rank 8 после 64 шагов. По умолчанию используется
  исходная модель. На40сложных сценариях она дала36/36полных генераций против29/36
  у этого LoRA и меньшую задержку. `-UseAdapter` включает старый адаптер явно только
  для сравнения; уменьшение тренировочного loss не доказывает улучшение ответов.
- Отдельно обучен кандидат `rag-v2`:108дополнительных шагов на синтетических
  RU/KK/UZ ответах с правилами. На полном сравнении он дал больше ошибок, поэтому
  не заменяет рабочий адаптер. Воспроизведение эксперимента и ограничения:
  [experiments/rag-training/README.md](experiments/rag-training/README.md).
- **intfloat/multilingual-e5-small**, ревизия
  `614241f622f53c4eeff9890bdc4f31cfecc418b3`: CPU, masked mean pooling, L2,
  префиксы `query:`/`passage:`, 384 измерения, до 512 токенов.
- BM25 + reciprocal rank fusion + подсказки раздела для событий. Для 288 документов
  достаточно точного NumPy-поиска; внешний векторный сервер не нужен.
- Собственный обученный CPU-классификатор: существующий E5 и линейные головы
  на14категорий/4приоритета,777обучающих примеров. Нет эталонных меток:
  обучение на слабой разметке текста игрока и синтетических примерах. При
  неуверенности — явный возврат к ключевым словам; модель не снижает приоритет
  распознанных опасных тем. E5 используется совместно с поиском, второй копии нет.
- 266 полных пунктов, 14 терминов и восемь контекстных записей из 11 разделов.
  Канонический ключ `rules:<section_id>:<ref>` различает совпадающие номера.
  Термины имеют внутренние ключи и не выдаются за официальные номера пунктов.

Поток: JSON → восстановление legacy KK при достаточном контексте → только сообщения
игрока → E5-классификатор и независимые правила приоритета → E5+BM25 →
консервативный фильтр темы → отобранные правила и неподтверждённый диалог → Qwen → проверки ответа →
черновик для сотрудника. Ответы администратора, verdict/punishment/violation/status
исключены. Поле `has_evidence` обозначает только наличие вложений; изображений нет.
Фильтр темы использует явный список проверенных соответствий и снижает полноту:
для платежей/аккаунтов FAQ в handout отсутствует, поэтому общие игровые правила
не подставляются как инструкция по восстановлению или возврату денег.

## Запуск в текущей среде Windows

Из корня проекта, PowerShell, используется существующий `.venv-soup`:

```powershell
# Проверить/подготовить только знания и embedding-модель. Без флага сеть не используется.
.\.venv-soup\Scripts\python.exe -X utf8 scripts/prepare_rag_assets.py
# На новом компьютере разрешённая первоначальная загрузка E5:
.\.venv-soup\Scripts\python.exe -X utf8 scripts/prepare_rag_assets.py --handout C:\path\handout.zip --download-embedding

# Полный RAG + исходная Qwen3-8B, один процесс / один GPU:
.\scripts\run-rag.ps1 -Action check
.\scripts\run-rag.ps1 -Action serve
# Текущий выбранный запуск с обновлёнными метриками:
.\scripts\run-rag.ps1 -Action serve -EvaluationReport .private/input-v4/metrics36.json
# Вариант с экспериментальным адаптером:
.\scripts\run-rag.ps1 -Action serve -UseAdapter
# Явный выбор той же рабочей версии:
.\scripts\run-rag.ps1 -Action serve -AdapterVersion smoke
# Старые бэкенды сохранены для воспроизведения:
.\scripts\run-rag.ps1 -Action serve -Backend resident -UseAdapter
.\scripts\run-rag.ps1 -Action serve -Backend stream -UseAdapter
```

Сервер слушает `http://127.0.0.1:8000`: на главной странице форма обращения,
измеренные метрики и12реальных ответов из синтетического прогона. Схема и
интерактивные API-запросы: `http://127.0.0.1:8000/docs`. Остановка: Ctrl+C.
Не запускайте второй процесс с моделью одновременно с сервером или обучением.
Используется локальный API без аутентификации; наружу его не публикуем.
`-AdapterVersion rag-v2` предназначен только для воспроизведения отклонённого
эксперимента. Параметр включает указанный адаптер явно и восстанавливает переменные
окружения после выхода. Обычный запуск использует исходную модель без LoRA; параметры адаптера нужны для сравнения экспериментов.

## HTTP API v2

Все ответы, включая ошибки, имеют сгенерированный сервером заголовок
`X-Request-ID`. Текст обращения и исключения не возвращаются в ошибках.

| Метод и путь | Назначение |
| --- | --- |
| `GET /` | Страница обращения, метрик и примеров |
| `GET /live` | Жив ли HTTP-процесс; не обращается к модели |
| `GET /ready`, `GET /health` | Готовность знаний и включённого генератора; 503 при отказе |
| `GET /v1/meta` | Категории, приоритеты, языки, версия корпуса и ограничения |
| `POST /v1/rag/search` | Поиск и консервативный отбор правил без генерации |
| `GET /v1/rag/rules/30/2.1` | Полный пункт по разделу и номеру; 404, если отсутствует |
| `POST /triage` | Классификация, RAG и черновик для сотрудника |
| `POST /v1/classify` | Только CPU-классификация, без генерации |
| `GET /v1/evaluation` | Метрики36синтетических сценариев и12примеров |
| `GET /v1/classifier/metrics` | Отдельные измерения классификатора и связки с правилами |
| `GET /v1/robustness` | Отдельные40проверок языков, опечаток, ложных ссылок и невидимых вложений |

`-KeywordClassifier` явно отключает обученную голову для сравнения. При
`-LexicalOnly` нет E5, поэтому классификация также явно возвращается к правилам.
Для обученной версии нужны `.private/classifier-v1/model/{manifest.json,weights.npz}`.
`COPILOT_CLASSIFIER_PATH` меняет путь к модели; `COPILOT_CLASSIFIER=0|1` — выбор.
API проверяет хеши таксономии/энкодера/весов. Отсутствие или порча включённой
модели — ошибка запуска, а не скрытая подмена. `COPILOT_EVALUATION_REPORT_PATH`
задаёт приватный JSON-отчёт; по умолчанию `.private/rag-v3/metrics.json`.

Сервис принимает loopback Host; запросы записи с посторонним Origin отклоняются.
Страница показывает текст через `textContent`, без интерпретации ответов как HTML.

Пример тела поиска: `{"query":"Ойыншы мені қорлады","limit":3}`.
Дополнительные поля: `rule_refs` (до20строк) и `lang` (подсказка языка).
Ответ содержит `query_lang`, `results`, `warnings`, `corpus_version` (SHA256)
и `elapsed_ms`. Каждый результат содержит `canonical_id`, `section_id`,
`section_title`, `ref`, `text`, `score`, `source_type`.
`score` — относительный ранг, не вероятность применимости.

Для событий с противоположными правилами неоднозначный контекст может дать
пустой результат. Платёжный/аккаунтный FAQ отсутствует: сервис возвращает
`no_verified_applicable_rule`, а не подставляет игровые правила.
Поиск учитывает Unicode, казахские буквы и варианты узбекского апострофа.
Узкие переводы ключевых слов расширяют только лексический запрос; E5 получает
исходный текст. Фильтр темы и языковые проверки остаются эвристическими;
классификатор обучен на слабых метках и использует резервные правила.
Фильтр различает явно отрицаемое событие и цитирование правила другого события;
неразрешимое сравнение нескольких событий по-прежнему требует уточнения.
Legacy-символы казахского текста восстанавливаются при KK/KZ-контексте или
характерном сигнале; обычные неоднозначные украинские буквы глобально не меняются.
Для поиска/классификации применяется ограниченный словарь опечаток и основ слов;
исходный текст утверждения и числовые ссылки не исправляются. Имена/ссылки/handles
защищаются от словарной замены. Смешанные языки определяются по совокупности слов,
а не по одной букве. При отсутствии данных — `und`, уточнение языка без E5/LLM.
Подсказка сервера может разрешить языковую ничью, но не превращает emoji в казахский.

Классификатор и поиск переиспользуют один query-вектор. RAM-кэш ограничен128
векторами/300секундами (~192KiBданных): только векторы и хеши точного текста,
без текста обращений/ответов; сбрасывается при перезагрузке/закрытии. Вариант
`COPILOT_QUERY_CACHE=0` отключает кэш для сопоставимого CPU-измерения.

Генерация и поиск имеют отдельные ограничения допуска: по одному запросу,
без очереди; повторная работа того же типа получает503 `busy`.
Поиск и `/live` доступны во время генерации. Первый `/triage` также использует
общую блокировку чтения индекса; это не обещание произвольного параллелизма.
Lifespan загружает модель до начала обслуживания HTTP, поэтому `/live` не является
отдельным портом наблюдения за первоначальной загрузкой.

```powershell
$payload = @{
  kind='complaint'
  messages=@(@{role='player';text='Игрок оскорбил меня в чате, сервер 12';attachments=1})
} | ConvertTo-Json -Depth 5
Invoke-RestMethod http://127.0.0.1:8000/triage -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($payload))

# Пакетный запуск без сервера. Выход должен быть новым файлом.
.\scripts\run-rag.ps1 -Action predict -InputPath experiments/rag/synthetic-input.jsonl -OutputPath .private/my-predictions.jsonl
```

Вход `.jsonl`/`.jsonl.gz`, одна запись на строку. CLI сохраняет порядок, ограничивает
строку 128 KiB, завершает запись атомарно только после успеха всего пакета,
отказывается перезаписывать вход или существующий выход. Ошибка содержит номер строки,
без текста обращения. Также доступны `copilot predict --input ... --output ...`
и переменные `COPILOT_INPUT`/`COPILOT_OUTPUT` (`INPUT`/`OUTPUT` для совместимости).

Для проверки поиска и маршрутизации **без LLM**:

```powershell
.\scripts\run-rag.ps1 -Action serve -TemplateOnly
.\scripts\run-rag.ps1 -Action predict -TemplateOnly -InputPath experiments/rag/synthetic-input.jsonl -OutputPath .private/template-predictions.jsonl
```

Это явно обозначается в `/health` как `explicit_template_baseline`; такой запуск
не измеряет качество или скорость генерации. `-LexicalOnly` дополнительно отключает
E5 явно. Если E5 включён, но отсутствует, загрузка завершается ошибкой.

## Настройки и ограничения

`COPILOT_RULES_PATH`, `COPILOT_TAXONOMY_PATH`, `COPILOT_MODEL_PATH`,
`COPILOT_ADAPTER_PATH`, `COPILOT_EMBEDDING_PATH`, `COPILOT_INDEX_DIR`,
`COPILOT_RUNTIME_DIR` задают локальные пути. `COPILOT_NUM_THREADS=4`,
`COPILOT_GENERATION_TIMEOUT=45`, `COPILOT_MAX_NEW_TOKENS=160` — значения по умолчанию.
Флаги `COPILOT_GENERATION`, `COPILOT_DENSE`, `COPILOT_USE_ADAPTER`: `0`/`1`.
Запускатор явно устанавливает эти три флага по своим параметрам и восстанавливает
окружение после завершения.
`COPILOT_BACKEND=llamacpp|resident|stream` выбирает бэкенд явно;
`-Backend` в запускаторе переопределяет его на один запуск. Native-пути:
`COPILOT_GGUF_PATH`, `COPILOT_GGUF_ADAPTER_PATH`, `COPILOT_LLAMA_BINARY_PATH`,
порт `COPILOT_LLAMA_PORT=8081`. На отказе бэкенд автоматически не меняется.

Генерация: до 1024 токенов входа, до пяти выдержек по 600 символов; исключённые и
сокращённые пункты отмечаются в приватной диагностике. Сообщение игрока не обрезается:
слишком длинный контекст вызывает безопасный шаблонный ответ. Ответ без EOS не считается
полным. В native-режиме действует HTTP-таймаут к дочернему серверу; отмена текущей
GPU-задачи после разрыва соединения отдельно не подтверждена. У torch-бэкендов
дедлайн кооперативный между токенами. 45 секунд не являются строгим HTTP SLA.

При таймауте, неполном выводе, неподдерживаемом языке или отклонении проверкой
возвращается локализованный шаблон и явная причина. Язык определяется эвристикой;
генерация проверяется для RU/KK/UZ/EN, для ES/PT используются шаблоны,
для `und` — русский запрос уточнить язык с кодами выбора. Проверки ссылок, обещаний, секретов и
заявлений о доказательствах не гарантируют семантическую правильность. Сотрудник
обязан проверить и отредактировать черновик. Ссылка на существующий пункт сама по
себе не доказывает его применимость; спорные случаи требуют проверки человеком.

Платежи, доступ к аккаунту, обжалование блокировки и действия администрации требуют
человека независимо от категории. Не просим пароль, OTP или полные реквизиты.
Дубликаты: только точное совпадение нормализованного текста, автора, kind и времени
в пределах часа; хранилище на 4096 ключей живёт только в текущем процессе.
Без автора или timezone в created_at дубликат не устанавливается. Детектор спама
ещё не обучен; короткое «помогите» само по себе не считается спамом.

Кэш E5 учитывает хеши источника, локальной модели и параметры кодирования.
Приложение не загружает модель из сети, не отправляет данные внешним API,
не логирует текст обращений в HTTP access log. Локальные диагностические файлы
с полными ответами сохраняются в игнорируемой `.private`.

## Установка на другом компьютере

Python3.11+, NVIDIA CUDA GPU и свободное место для весов. Сначала установите
совместимую CUDA-сборку PyTorch по официальной инструкции, затем в отдельном venv:
`python -m pip install -e ".[native,dev]"` для native-режима. Soup/BNB дополнительно:
`python -m pip install -e ".[inference]"`. Текущая среда фиксируется
в `experiments/inference/requirements-lock.txt`; это снимок конкретной Windows/CUDA-среды,
а не универсальный lock для всех ОС. Новый чистый компьютер здесь не проверялся.

E5 готовится указанным выше скриптом. Native runtime, локальная конвертация и пути:
[experiments/inference/README.md](experiments/inference/README.md).
Для исходных HF-весов и старого Soup-кэша: `experiments/soup/README.md`;
повторно обучать модель ради запуска API не нужно. Все артефакты остаются в `.private`.
Другие модели/ОС требуют отдельной проверки; проверена текущая Windows.

```powershell
.\.venv-soup\Scripts\python.exe -m pytest -q --basetemp=.private/pytest-rag
.\.venv-soup\Scripts\python.exe scripts/smoke_rag_api.py --output .private/http-template-new.json

```

Таймаут сервера45секунд; старый `stream` можно диагностировать с явным лимитом180.
Сохраняются исходный вывод, полный EOS или
причина остановки, итог после проверки, одинаковые документы для base/adapter,
время и ошибки. Фиксированный порядок base→adapter и прогрев кэша могут смещать
замеры. Маленькая синтетическая выборка не является оценкой SLA или качества.

В sandbox Windows TestClient может зависать до старта приложения на socketpair;
для проверок нужен обычный локальный процесс с разрешением loopback. Для tempfile
при ограничениях укажите TMP/TEMP внутри `.private`. Не считайте такую ошибку
пройденным тестом и не отключайте проверки.
