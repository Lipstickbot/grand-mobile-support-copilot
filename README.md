# Grand Mobile Support Copilot

Локальный помощник поддержки Grand Mobile: классификация обращений, поиск по
правилам игры и черновик ответа на русском, казахском, узбекском или английском.
Каждый черновик проверяет сотрудник поддержки.

## Запуск

Из корня проекта в PowerShell, когда локальная среда и ресурсы уже подготовлены:

```powershell
.\scripts\run-rag.ps1 -Action serve -EvaluationReport .private/input-v4/metrics36.json
```

Открыть приложение: **http://127.0.0.1:8000**. Документация API:
**http://127.0.0.1:8000/docs**. Остановка — `Ctrl+C` в терминале сервера.
Если сервер уже работает, откройте адрес приложения; второй процесс модели не нужен.

Проверка готовности из другого терминала:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/ready
```

## Что нужно для запуска

Проверенное окружение: Windows, Python 3.12, RTX 3060 Laptop с 6 ГБ VRAM.
Используются Qwen3-8B Q4_K_M через llama.cpp CUDA и multilingual-e5-small на CPU.
Зависимости приложения перечислены в `pyproject.toml`; проверенный состав
окружения — в `experiments/inference/requirements-lock.txt`.

Веса, исходные данные и локальная среда не хранятся в репозитории. Перед первым
запуском на новом компьютере подготовьте `.venv-soup`, PyTorch и ресурсы:

- `.private/data/rules.json` и `taxonomy.json` из разрешённого набора данных;
- `.private/models/qwen3-8b/` и `multilingual-e5-small/`;
- `.private/models/qwen3-8b-gguf-local/Qwen3-8B-Q4_K_M.gguf`;
- `.private/tools/llama-b11960/llama-server.exe`;
- `.private/classifier-v2-authored/model/` с обученными локальными головами классификатора;
  профиль v1 остаётся для сравнения через `-ClassifierProfile baseline`.

[Подробная подготовка, параметры и API](RAG.md). Отчёты в `.private` необязательны
для обработки обращений; без них соответствующие разделы метрик будут недоступны.
Пустой clone без этих ресурсов не запускает модель автоматически.

## API

| Запрос | Назначение |
| --- | --- |
| `POST /triage` | Категория, приоритет, найденные правила и черновик |
| `POST /v1/classify` | Классификация без генерации |
| `POST /v1/rag/search` | Поиск по правилам |
| `GET /ready` | Готовность сервиса |
| `GET /v1/quality` | Сравнение измеренного качества |

## Проверка кода

```powershell
.\.venv-soup\Scripts\python.exe -X utf8 -m pytest -q
```

Для проверок интерфейса нужен Node.js. Измерения с реальной моделью требуют
локальных ресурсов; приватные сценарии и обращения игроков не публикуются.

## Качество

На известных синтетических примерах: категория **23/42**, приоритет p0 на
критичном stress-наборе **15/16** (категория вместе с p0 — **11/16**),
псевдоссылки **0/100**, нужная ссылка **43/63**, p95 **2,99 с**.
Это не независимая человеческая точность. Часть метрик снизилась;
все черновики требуют сотрудника. Новые LoRA и расширенный промпт не выбраны.

[Аудит, сравнение моделей, данные и итоговые проверки](docs/TECHNICAL_REPORT.md).
Для независимой оценки подготовлены 49 реальных обращений без train-пересечений,
но человеческих меток пока **0**: [протокол](docs/REVIEW_PROTOCOL.md).

Batch из PowerShell:

```powershell
.\scripts\run-rag.ps1 -Action predict -InputPath .private/input.jsonl -OutputPath .private/predictions-new.jsonl
```

Перед batch остановите HTTP-процесс модели. С активированной подготовленной
Python-средой и установленным GNU Make также есть `make predict IN=... OUT=...`.
На текущем Windows GNU Make отсутствует; реальный batch CLI проверен.
