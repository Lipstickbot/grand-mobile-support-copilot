# Отчёт: Support Copilot v3 — классификация, RAG, черновики на 6 языках

Все цифры получены на `tickets_valid.jsonl` (1000 обращений: 817 жалоб, 183 репорта)
командой `make eval` и сохранены в `.private/v3/metrics.json`.
Скрытый тест не использовался.

## Главная идея

Старая версия обучала классификатор на **164 придуманных примерах** и не использовала
118 337 реальных тикетов. Причина: в train нет разметки категорий. Но в ответах админов есть
**исход** (вердикт, код нарушения `2.1 ОП`, `1.2 GZ`, `5.2`, `DM`, апелляция). v3 переводит этот
исход в категорию таксономии (weak supervision, `v3/labels.py`) и учит модель предсказывать её
**только по тексту игрока**. Ответы админов на инференсе не используются.

## Что изменено

**Классификация** (`v3/model.py`, `v3/labels.py`, `v3/multilang.py`)
- Weak-разметка 118 тыс. тикетов: код нарушения из ответа админа → категория, апелляции → admin,
  `invalid_format` и пункты правил подачи жалоб → invalid, ключевые слова RU/UZ как запасной вариант.
- TF-IDF (символы 2–5 + слова 1–2) → LinearSVC, отдельно для жалоб (без весов классов) и репортов
  (со взвешиванием, чтобы не терять редкие платёж/аккаунт). Обучение ~90 с на CPU.
- Для языков, которых мало в обучении (kk, en, es, pt, украинский), работает многоязычный
  словарь ключевых слов поверх модели.
- Защитные правила: платёж/взлом → `report.payment/account` и p0 (в том числе
  «купив…не з'явився»), угроза жизни → p0, пустое описание → `complaint.invalid`.

**RAG** (`v3/pipeline.py: retrieve`, `v3/rulekb.py`)
- Обученная «голова правил»: LinearSVC по 42 пунктам, которые админы реально применяли
  (27 тыс. жалоб).
- Номера пунктов разбираются с учётом раздела: `2.1 ОП` → 30, `1.2 GZ` → 32,
  `1.2.7 правил подачи жалоб` → 31. Плюс приоритет пунктов таксономии и BM25.
- Пункт цитируется, только если он сильно поддержан и согласуется с категорией.
- `cited` в формате контракта (`["2.1"]`), каноничный id лежит в `reasons`.

**Черновики** (`v3/templates.py`, `v3/sanctions.py`, `v3/llm.py`)
- Шаблоны на **6 языках игры**: ru, kk, uz (латиница), en, es, pt, в стиле реальных ответов
  админов («Уважаемый игрок, благодарим…», «Hurmatli o‘yinchi…»). Украинский текст получает
  ответ на русском.
- **Санкция из правила**, только условно и дословно по тексту пункта: «Если нарушение
  подтвердится, по этому пункту правилами предусмотрено: MUTE от 15 до 30 мин». Переведена на
  все 6 языков. Если формулировку не удалось полностью разобрать, санкция не выводится. Есть в 44% черновиков.
- Без обещаний разбана, возврата или наказания: решение всегда за администратором,
  проверка регулярным выражением `PROMISE` на каждом черновике.
- LLM опциональна (`COPILOT_V3_LLM_URL`, OpenAI-совместимый API, например ваш llama-server).
  Она только переписывает шаблон и получает найденные пункты и 3 похожих реальных ответа админов.
  Ответ отбрасывается и остаётся шаблон, если в нём: пункт не из найденных, обещание, потерянная
  цитата, кириллица в uz или таймаут > 3.5 с.

**needs_human:** всегда человек — `needs_human_always` из таксономии, p0, платежи / взлом /
апелляции, жалобы с решением о наказании, репорты, требующие действия в игре, вопросы без ответа
LLM, низкая уверенность. Автоматически — оффтоп, жалобы без описания (п. 1.2.3), дубли (п. 1.2.9).

**Бонусы**
- Дедупликация: один заявитель, та же цель или похожий текст в течение 60 минут.
  Пустые репорты помечаются как спам (на valid отмечено 44).
- Шаблоны из кластеров ответов админов: `scripts/mine_templates_v3.py`.
- **Интерфейс админа**: `http://127.0.0.1:8000/` — очередь с фильтрами, черновик, исправление
  категории, кнопки «Отправить», «Сохранить правку», «Эскалировать». Каждое действие пишется
  в `.private/v3/feedback.jsonl` (черновик, итоговый текст, правка, исправленная категория) как обучающий сигнал.

## Стоимость и латентность

- Без LLM: $0, CPU, p95 = 6 мс на тикет.
- С локальным Qwen3-8B (llama.cpp): $0. Латентность ограничена таймаутом 3.5 с, после него используется шаблон.
- С облачной LLM: примерно 700 входных + 120 выходных токенов. По цене небольшой модели
  ($0.15 / $0.60 за 1M) выходит ≈ $0.00018 за тикет, в 10 раз ниже лимита $0.002.
  Фактические токены считаются в `llm.stats`.

## Запуск

```bash
pip install -e ".[dev,llm]"
make train      # ~2 мин на CPU -> .private/v3/
make test
make serve      # http://127.0.0.1:8000/ + POST /triage
make predict IN=tickets.jsonl OUT=pred.jsonl
make eval       # -> .private/v3/metrics.json
```

На Windows без make: `.\scripts\run-v3.ps1 -Action train|serve|predict|eval|test -Python python`.

## Ограничения (честно)

- Weak-разметка — это эвристика по ответам админов, а не разметка Grand. В спорных местах
  таксономии («помогите» — offtopic или help; апелляция — admin или invalid) модель повторяет мои решения.
- Ручная разметка 160 тикетов сделана одним разметчиком.
- На valid почти нет kk/en/es/pt (9/4/1/1 тикетов после исправления детектора: большинство «kk»
  в данных были украинскими). Качество для этих языков проверено только на синтетических примерах в тестах.
- Шаблоны kk/uz/es/pt не проверены носителями.
- Черновики с LLM не замерены: в среде разработки нет GPU.
