# Отчёт: Grand Mobile Support Copilot

Все цифры получены на `tickets_valid.jsonl` (1000 обращений: 817 жалоб, 183 репорта) командой
`make eval` и сохраняются в `.private/v3/metrics.json`. Скрытый тест не использовался.

## Идея

В `tickets_train.jsonl.gz` нет разметки категорий, но в ответах администраторов есть **исход**:
вердикт, код нарушения (`2.1 ОП`, `1.2 GZ`, `5.2`, `DM`), апелляция. Мы переводим этот исход в категорию
таксономии (weak supervision, `v3/labels.py`) и учим модель предсказывать её **только по тексту игрока**.
Ответы администраторов используются только для обучения, на инференсе их нет.

![F1 по категориям](assets/per_class_f1.png)

**Про `complaint.invalid` (F1 0.19 vs weak-разметка).** Weak-разметка считает invalid всё, что админ
отклонил за оформление, в том числе содержательные жалобы («хотела заскамить на машину»).
Сервис классифицирует по смыслу и никогда не отклоняет автоматически жалобу, в которой описано
нарушение: такая жалоба получает категорию нарушения и уходит человеку. Ручная разметка
подтверждает этот выбор.

## Как устроено

**Классификация** (`v3/model.py`, `v3/labels.py`, `v3/multilang.py`)
- Weak-разметка 118 тыс. тикетов: код нарушения из ответа админа → категория, апелляции → admin,
  `invalid_format` и пункты правил подачи жалоб → invalid, ключевые слова RU/UZ как запасной вариант.
- TF-IDF (символы 2–5 + слова 1–2) → LinearSVC, отдельно для жалоб и репортов (у репортов со
  взвешиванием классов, чтобы не терять редкие платёж/аккаунт). Обучение ~90 с на CPU.
- Для языков, которых мало в обучении (kk, en, es, pt, украинский), есть многоязычный словарь поверх модели.
- Защитные правила: платёж/взлом → `report.payment/account` и p0; угроза жизни → p0;
  пустое описание → `complaint.invalid`, но описанное нарушение никогда не считается пустым;
  голое «помогите» → `report.offtopic` (пример из таксономии).

**RAG** (`v3/pipeline.py: retrieve`, `v3/rulekb.py`)
- Обученная «голова правил»: LinearSVC по 42 пунктам, которые админы реально применяли (27 тыс. жалоб).
- Номера пунктов разбираются с учётом раздела: `2.1 ОП` → 30, `1.2 GZ` → 32,
  `1.2.7 правил подачи жалоб` → 31. Плюс приоритет пунктов таксономии и BM25.
- Пункт цитируется, только если он сильно поддержан и согласуется с категорией.
  Пункты Зелёной зоны — только если в тексте есть признак ЗЗ (место из списка ЗЗ, «зз», «gz»)
  или игрок сам назвал пункт.
- `cited` в формате контракта (`["2.1"]`), каноничный id лежит в `reasons`.

**Черновики** (`v3/templates.py`, `v3/sanctions.py`, `v3/llm.py`)
- Шаблоны на **6 языках игры**: ru, kk, uz (латиница), en, es, pt — в стиле реальных ответов
  администраторов. Украинский текст получает ответ на русском.
- **Санкция из правила**, только условно и дословно по тексту пункта: «Если нарушение
  подтвердится, по этому пункту правилами предусмотрено: MUTE от 15 до 30 мин». Если формулировку не
  удалось полностью разобрать, санкция не выводится.
- Без обещаний разбана, возврата или наказания: решение всегда за администратором,
  каждый черновик проверяется регулярным выражением `PROMISE`.
- LLM опциональна (`COPILOT_V3_LLM_URL`, OpenAI-совместимый API). Она только переписывает шаблон
  и получает найденные пункты и 3 похожих реальных ответа админов как образец стиля. Ответ
  отбрасывается, если в нём пункт не из найденных, обещание, потерянная цитата, кириллица в uz или таймаут > 3.5 с.

**needs_human:** всегда человек — `needs_human_always` из таксономии, p0, платежи / взлом /
апелляции, жалобы с решением о наказании, репорты, требующие действия в игре, вопросы без ответа
LLM, низкая уверенность. Автоматически — оффтоп, жалобы без описания (п. 1.2.3), дубли (п. 1.2.9).

**Бонусы**
- Дедупликация: один заявитель, та же цель или похожий текст в течение 60 минут; пустые репорты
  помечаются как спам.
- Шаблоны из кластеров ответов админов: `scripts/mine_templates_v3.py`.
- Интерфейс админа: `http://127.0.0.1:8000/` — очередь, черновик, исправление категории,
  «Отправить / Сохранить правку / Эскалировать»; действия пишутся в `.private/v3/feedback.jsonl`
  как обучающий сигнал.

## Стоимость и латентность

- Без LLM: $0, CPU, p95 = 7 мс на обращение.
- С локальной LLM (например Qwen3-8B через llama.cpp): $0; латентность ограничена таймаутом 3.5 с, после него используется шаблон.
- С облачной LLM: примерно 700 входных + 120 выходных токенов. По цене небольшой модели
  ($0.15 / $0.60 за 1M) выходит ≈ $0.0002 за обращение, в 10 раз ниже лимита $0.002.

## Запуск

```bash
pip install -e ".[dev,llm]"
make train      # ~2 мин на CPU -> .private/v3/
make test
make serve      # http://127.0.0.1:8000/ + POST /triage
make predict IN=tickets.jsonl OUT=pred.jsonl
make eval       # -> .private/v3/metrics.json
```

На Windows без make: `.\scripts\run-v3.ps1 -Action train|serve|predict|eval|test -Python python`.

## Ограничения

- Weak-разметка — эвристика по ответам админов, а не разметка Grand; в спорных местах таксономии
  модель повторяет наши решения.
- Ручная разметка и проверка ответов сделаны одним разметчиком.
- На валидации почти нет kk/en/es/pt (9/4/1/0 обращений); качество для них проверено на синтетических примерах в тестах.
- Шаблоны kk/uz/es/pt не проверены носителями.
- Черновики с LLM не замерены: в среде разработки не было GPU.
