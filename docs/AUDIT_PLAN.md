# Аудит и план улучшений — 31 октября 2026

Это план до новых изменений в рабочем конвейере. Данные, веса и примеры остаются
в `.private/`. Публикация изменений требует отдельного подтверждения пользователя.

## Что уже существует

`POST /triage` → Pydantic → текст **только player** для языка/категории →
восстановление legacy-KK и ограниченная коррекция опечаток → frozen
multilingual-e5-small CPU + две class-balanced ridge головы → keyword safety floor →
BM25 + dense RRF + событийные/лексические поправки → фильтр применимости →
Qwen3-8B Q4_K_M в llama.cpp CUDA либо шаблон сбора сведений → защитный фильтр → JSON.

Категория и приоритет принимаются вне LLM. В генерацию попадает также реплика
reported_player как недоверенное утверждение; admin и поля исхода исключены.
Каждый ответ имеет `needs_human=true`. Есть loopback boundary, лимит тела,
таймаут, сериализация GPU-запросов, атомарный batch CLI и безопасные NPZ-веса.

## Этапы и условия

1. Аудит всех исходников, требований DOCX и handout; агрегаты без исходных текстов.
2. Сравнение классификаторов и воспроизводимые разрезы kind/lang, confusion matrix.
   Проверенный реальный holdout появится только после независимой разметки людьми.
3. Отдельная priority policy, минимальное усиление guard, сохранение существующего RAG;
   ablation поиска до любых усложнений и никаких автоматически принятых санкций.
4. Структурированный пакет для генератора и совместимый `make predict`.
5. Unit/regression, настоящий HTTP на тех же сценариях, latency включая ошибки;
   стоимость внешнего API=0, электричество/амортизация измерены не были.
6. Отчёт до/после, оставшиеся пробелы, работающий локальный сервер. Без git push.

Полноценный Transformer fine-tuning классификатора пока не обоснован: есть GPU,
но нет достаточно проверенных меток. Увеличение числа шагов на псевдометках
не решает эту проблему. Отказ от замены работающего компонента тоже результат.
